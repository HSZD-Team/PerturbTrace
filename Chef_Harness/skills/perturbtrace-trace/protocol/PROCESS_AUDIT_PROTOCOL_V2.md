# PerturbTrace Process-Edge Audit Protocol v2.0

Frozen on 2026-07-20 before v2 semantic coding. This retrospective audit reads completed run artifacts only and does not rerun experiments or modify run roots.

The audit unit is the transition `F_t -> S_(t+1) -> A_(t+1) -> O_(t+1)`. Every completed round after the first contributes one transition; round 1 supplies the initial externalized scientific prior/state and initial action only. The frozen five-round formal study therefore contributed four transitions per trajectory.

`S_(t+1)` is the scientific content explicitly recorded in the submitted rationale: hypotheses/mechanisms, evidence stance, stated uncertainty, and next-round search strategy. It is an auditable public decision interface, not latent belief or hidden reasoning. Missing content is not inferred from actions or outcomes.

Feedback-to-State fields are grounding (`0/1/2`), operation (`maintain_reinforce`, `expand`, `narrow_prune`, `pivot`, `mixed`, `none`, `unclear`), and calibration (`calibrated`, `over_attributed`, `unclear`). Random-feedback grounding and calibration are judged against delivered feedback, never hidden truth. Composite labels are mutually exclusive in this order: no feedback -> `not_applicable_control`; grounding 0 or operation none -> `no_observable_update`; grounding 1, operation unclear, or calibration unclear -> `indeterminate`; grounding 2 plus explicit operation plus over-attribution -> `over_attributed_update`; grounding 2 plus explicit operation plus calibrated inference -> `calibrated_update`.

State and action are coded independently. State coders see public task context, previous rationale/state text, delivered feedback, current rationale, and the frozen task vocabulary. They do not see current actions, agent identity, condition label, or outcomes. Explicit anaphora such as "continue the previous core strategy" may resolve against the previous rationale; silent carry-forward is prohibited. Action composition is built from public gene annotations and a frozen task-specific primary-module map, without rationale, feedback, condition, agent identity, or outcomes.

For accepted batch size 128, a module is absent at 0 genes, minor at 1-12 genes, and major at 13 or more genes. The portable implementation uses the equivalent 10% major threshold and marks a batch unassessable when more than 30% of actions map to `other_uncertain`; the original 128-action thresholds are 13 and 39. Maintain requires retained modules not to decrease. Expand requires retained directions not to decrease and at least one priority-up module to increase. Narrow/prune requires at least one priority-down module to decrease and retained-module concentration to increase. Pivot requires a priority-up module to become major and a previously major priority-down module to fall to minor/absent. Mixed checks every explicitly declared component. State-to-Action is `aligned`, `partially_aligned`, `mismatch`, or `unassessable`. A task without an explicit matching public codebook is unassessable for this edge; it is not silently mapped to another task vocabulary.

For a transition selecting `A_(t+1)`, `N_t` and `H_t` are the remaining candidate and hidden-hit counts after removing `A_1...A_t`. With accepted batch size `b_(t+1)` and true hits `h_(t+1)`, `RHE=(h/b)/(H/N)`. Under `X ~ Hypergeom(N,H,b)`, upper-tail probability <=0.025 is `enriched`, lower-tail probability <=0.025 is `depleted`, otherwise `expected_range`. If `H=0`, RHE is NA and outcome is `no_hits_remaining`. All policies use hidden truth, never displayed random counts.

Primary rates retain their explicit eligible denominators. Calibrated-update rate uses all feedback-available transitions. Action-translation rate uses established Feedback-to-State transitions with assessable State-to-Action; only aligned is numerator. Outcome-enrichment rate uses oracle-computable transitions with remaining hits. Full-chain completion uses feedback-available oracle-computable transitions; numerator is calibrated update plus aligned action plus enriched outcome. When a manifest includes true and random conditions, they are reported separately. A one-run or otherwise unpaired manifest is a case-level audit and does not support a condition contrast.

In the frozen formal panel, the 288 double-coded transitions contained one deterministic seed from every agent x task x condition x transition-position stratum, split into 144 development and 144 held-out confirmation transitions. For a user-supplied manifest, the implementation deterministically selects at least one packet per available group x condition x transition-position stratum, then fills a configured double-coding fraction and alternates the selected packets between development and confirmation. Coder A and coder B are independent medium-effort API passes with separate calls and reversed batch ordering; by default they use the same caller-supplied model, while distinct A/B model overrides are supported. Agreement is judge-judge, not human. Grounding uses quadratic weighted kappa; other fields use Cohen's kappa. When each held-out partition has the configured minimum packet count, every measured reliability field must reach kappa >=0.70 before remaining transitions are coded. Smaller manifests report agreement as not estimable rather than treating it as a pass. Full results never mix codebook versions.

Narrative descriptors may overlap and never replace the edge fields. `productive feedback adaptation` is true feedback + calibrated update + aligned action + enriched outcome. `feedback neglect` is feedback available + no observable update. `over-attributed response` uses over-attributed update. `rhetorical/incomplete translation` uses mismatch/partial alignment. `blind responsiveness` is random feedback + established state update + aligned action, with outcome class retained. No-feedback + enriched is a prior-driven-success transition.
